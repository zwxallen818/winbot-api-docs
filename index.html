窗宝遥控页 — 蓝牙协议接口文档

v260526 · 适用于泰山/贝多芬/白鲨S 机型 · 预研调试专用

概述 通用层 方向移动 硬件属性 手动喷水 清洁命令 读取属性 摇杆(旧) 时序流程

概述

本文档描述窗宝遥控页面（/remotestick）中 H5 与固件之间的全部蓝牙通信接口。所有蓝牙数据通过 sendBluetoothData(topic, payload) 函数发送，底层使用 MQTT over BLE 传输。


接口Topic方向频率说明
方向移动 move H5 → FW 按下即刻 + 100ms 轮询 D-Pad 十字键方向控制
硬件属性设置 setProperties H5 → FW 用户操作时单次 风机/水泵/滚刷参数下发
手动喷水 sprayWater H5 → FW 用户点击时单次 触发一次喷水
清洁命令 clean H5 → FW 用户操作时单次 开始/暂停/继续/停止清洁
读取属性 getProperties H5 → FW 进入页面/轮询 读取当前硬件状态
摇杆移动 (旧) wheelMove H5 → FW 100ms 轮询 全向摇杆，本版方向键不用

通用层 自动注入字段 & 加密规则

sendBluetoothData(topic, payload)

所有蓝牙数据发送的入口函数。框架会自动为每个 payload 注入以下字段：

字段类型生成规则说明
tsnumber Math.round(Date.now() / 1000) Unix 秒级时间戳，用于固件判断指令时效
seqnumber 0~999 循环递增 请求序列号，用于日志追踪和去重

加密规则

固件版本加密策略
≤ 1.2.5仅 setWifiList、SetApconfigV2 两个 topic 加密
> 1.2.5全部 topic 加密，但以下 豁免列表 除外

豁免加密的 topic（固件 > 1.2.5 时仍不加密）：

wheelsStart, wheelMove, move, auth_challenge, auth_verify,
initCentalManager, conPeripheralWithName, scanPeripherals,
downloadBinFile, downloadVoiceBinFile
重要：setProperties 和 clean 在新固件上会被 AES-CCM 加密，固件收到后需先解密再解析 JSON。

通用 payload 结构

发送前框架会将用户 payload 与自动字段合并：

// 用户调用：sendBluetoothData('move', { act: 'forward' })
// 实际发送：
{
  "act": "forward",   // 用户字段
  "ts": 1768363200,   // 框架自动注入
  "seq": 42           // 框架自动注入（0-999 循环）
}

Topic: move 方向移动

协议定义

Topicmove
方向H5 → 固件
加密豁免（不加密）
触发方式用户按下方向按钮
发送策略按下时立即发一条，随后每 100ms 定时轮询同一条指令
停止策略用户松手时停止轮询，不再发送

Payload 参数

参数类型必填说明
act string 是 移动方向，取值见下表

act 取值

值UI 文本含义
forward前进向上移动
backward后退向下移动
left左转向左转向
right右转向右转向

外窗方向映射

当用户选择 外窗模式（windowType = outer）时，左右方向会交换后再发送：

用户操作内窗发送外窗发送
左转leftright
右转rightleft
前进/后退不变

完整示例

// 用户按下「前进」按钮，内窗模式
// 第 1 条（立即）：
{ "act": "forward", "ts": 1768363200, "seq": 41 }

// 100ms 后第 2 条：
{ "act": "forward", "ts": 1768363201, "seq": 42 }

// ...持续轮询直到松手...

// 用户按下「左转」按钮，外窗模式 → 实际发 right
{ "act": "right", "ts": 1768363202, "seq": 43 }

Topic: setProperties 硬件属性设置

协议定义

TopicsetProperties
方向H5 → 固件
加密固件 > 1.2.5 时 AES-CCM 加密
触发方式用户操作开关/滑块/按钮
发送策略每次操作单次发送（非轮询）
说明每次发送 必须包含对应模块的全部字段（全量覆盖），不能只发变更字段

Payload 顶层结构

{
  "hardware": {
    "模块名": { /* 模块参数 */ }
  }
}

所有硬件模块都嵌套在 hardware 对象下。下面列出遥控页用到的三个模块。

模块一：吸附风机 suction_fan

参数类型范围说明
enable number 0 | 1 风机开关：0=关闭，1=开启
vacuum_level number 1 ~ 5 吸力档位（UI 上为开关，此值保持上次值或默认 3） 
// 打开吸附风机
sendBluetoothData('setProperties', {
  hardware: {
    suction_fan: {
      enable: 1,
      vacuum_level: 3
    }
  }
})

模块二：水泵 water_pump

注：当前遥控页通过 hideWaterPump prop 隐藏了水泵 UI，但协议仍保留供后续使用。

参数类型范围说明
enable number 0 | 1 水泵开关：0=关闭，1=开启
spray_amount number 1 ~ 5 喷水量档位，默认 3
work_interval number 0 ~ 19 秒 工作间隔，默认 3 秒
stop_interval number 0 ~ 19 秒 停止间隔，默认 3 秒 
// 打开水泵，3档喷水量，工作5秒停2秒
sendBluetoothData('setProperties', {
  hardware: {
    water_pump: {
      enable: 1,
      spray_amount: 3,
      work_interval: 5,
      stop_interval: 2
    }
  }
})

模块三：滚刷 roller_brush

参数类型范围说明
enable number 0 | 1 滚刷开关：0=关闭，1=开启
direction number 1 | 2 旋转方向：1=正转，2=反转
index number 1 | 2 滚刷选择：1=前滚刷，2=后滚刷
speed_level number 1 ~ 10 转速档位（对应 10~100 rpm），默认 6
转速换算：实际 RPM = speed_level × 10。speed_level=6 → 60rpm，speed_level=10 → 100rpm。 
// 开启前滚刷正转，6档转速（60rpm）
sendBluetoothData('setProperties', {
  hardware: {
    roller_brush: {
      enable: 1,
      direction: 1,
      index: 1,
      speed_level: 6
    }
  }
})

读取属性（Store 回传）

固件应向 H5 回传当前硬件状态，数据结构镜像下发格式，建议在以下时机回传：

  • H5 调用 getProperties 时
  • 硬件状态发生变化时主动推送
  • H5 进入遥控页面连接建立时
// 期望的回传结构（通过 Properties Store 同步）
{
  "hardware": {
    "suction_fan":  { "enable": 1, "vacuum_level": 3 },
    "water_pump":   { "enable": 1, "spray_amount": 3, "work_interval": 5, "stop_interval": 2 },
    "roller_brush": { "enable": 1, "direction": 1, "index": 1, "speed_level": 6 }
  }
}
兼容性说明：H5 也兼容 properties.suction_fan（无 hardware 包裹层）的旧格式，但新实现请使用 properties.hardware.suction_fan。

Topic: clean 清洁命令

协议定义

Topicclean
方向H5 → 固件
加密固件 > 1.2.5 时加密
触发方式用户点击清洁控制按钮
封装函数sendCleanCommand(act, content) → sendBluetoothData('clean', { act, content })

Payload 参数

参数类型必填说明
act string 是 清洁动作，取值见下表
content object 是 清洁参数对象

act 取值

值含义content 要求
start开始清洁需提供完整 content（type, direction 等）
pause暂停清洁content 从上次 start 的 workParams 自动继承
resume继续清洁content 从上次 start 的 workParams 自动继承
stop停止清洁content 可为空对象 {}

content 参数

参数类型默认值说明
type string — 清洁类型，取值见下表
border number 0 边框参数
direction string "normal" 工作方向："left" | "right" | "normal"
windowType string "inner" 窗户类型："inner"（内窗） | "outer"（外窗）
duration number 0 持续时间（0 表示不限制）

type 清洁类型枚举

值含义
auto自动清扫
depth深度清扫（分区清洁使用）
spot定点清扫
border沿边清扫
fine精细清扫
bathroom浴室清扫
heavy重度清扫
zone区域清扫
door玻璃门清洁
remote遥控模式

示例

// 开始深度清洁，向左，外窗
sendBluetoothData('clean', {
  act: 'start',
  content: {
    type: 'depth',
    border: 0,
    direction: 'left',
    windowType: 'outer',
    duration: 0
  }
})

// 暂停
sendBluetoothData('clean', { act: 'pause', content: { type:'depth', border:0, direction:'left', windowType:'outer', duration:0 } })

// 停止
sendBluetoothData('clean', { act: 'stop', content: {} })

Topic: getProperties 读取属性

协议定义

TopicgetProperties
方向H5 → 固件
加密固件 > 1.2.5 时加密
触发方式H5 进入页面时 / 需要同步状态时
期望响应固件应回传当前 Properties 全量状态（通过 MQTT 推送）

示例

// 查询当前属性
sendBluetoothData('getProperties', {})
// 或带特定查询参数
sendBluetoothData('getProperties', { keys: ['hardware'] })

Topic: wheelMove 摇杆移动 (旧协议，仅参考)

本版遥控页已用方向键（move topic）替代摇杆。以下为旧全向摇杆协议，保留供参考，固件侧仍需支持因其他页面可能调用。

TopicwheelMove
加密豁免（不加密）
发送策略100ms 轮询

Payload 参数

参数类型范围说明
anglenumber0 ~ 360摇杆角度（度）
speednumber1 ~ 3速度档位（遥控页固定为 2）
actstring"move"动作类型，固定值
// 摇杆推到 90°方向，2档速度
sendBluetoothData('wheelMove', { angle: 90, speed: 2, act: 'move' })
外窗模式下 angle 会做 360 - degree 的映射转换。

时序流程

方向键按下 → 松手

1 用户按下「前进」→ onDirectionPadMove({ direction: 'forward' })
2 检查 isAdsorption（未吸附不发送）
3 外窗判断：若 windowType === 'outer'，left↔right 互换
4 立即发送 sendBluetoothData('move', { act })
5 启动 100ms 定时器，重复发送同一条 move
6 用户松手 → onDirectionPadStop() → 清除定时器，停止发送

硬件属性修改

1 用户操作 UI 控件（开关/滑块/按钮）
2 组件更新本地 ref 状态
3 调用 setProperties({ hardware: { 模块: { ...全量字段 } } })
4 框架自动注入 ts + seq，判断是否需要加密
5 发送 BLE → 固件接收 → 执行 → 回传状态
6 H5 通过 watch(Properties) 监听回传，同步 UI

加密流程（固件 > 1.2.5）

1 sendBluetoothData(topic, payload) 被调用
2 检查 isBluetoothNeedEncrypt && enterprisePSK 是否有效
3 固件版本 > 1.2.5：判断 topic 是否在豁免列表
4 非豁免 → redCryptoManager.encryptAESCCM(payload) → 得到 { encrypted: ... }
5 加密后的数据通过 MQTT 发送
6 固件：收到后 AES-CCM 解密 → JSON.parse → 处理指令
